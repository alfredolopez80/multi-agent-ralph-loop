# Archived learning-integration tests

**Archived on**: 2026-08-25
**Issue**: #51 (test runner consolidation, part 2 → T17-retire)
**Verdict**: REMOVED — features superadas, not broken
**Action**: archived (not deleted) per issue #51 decision

## Why they are here

These two suites tested a learning subsystem whose wrapper layer was
retired when the project reached v3.0 (Unified Herding Blanket, 498556f,
and the v2.91.0 cleanup commit `42a1254`). They are not broken in
the sense that they have a defect — they describe correctly a world
the repo left behind.

Both suites share a single root cause: they assume an installed
`~/.claude-sneakpeek/zai/config/settings.json` plus a `learning-gate.sh`
hook under `~/.claude/hooks/`. Neither exists today:

| Suite | What it tested | What was retired |
|---|---|---|
| `test-learning-integration-v1.sh` | v2.81.2 Learning System integration: curator scripts, learning hooks, state dir, hook registration, procedural rules, docs | 4 layers: `$HOME/.claude-sneakpeek/zai/config/settings.json` (never installed in this repo), `$HOME/.claude/hooks/learning-gate.sh` (archived), `$HOME/.ralph/curator/scripts/` (curator scripts no longer in user install), `$HOME/.ralph/learning/state.json` (not generated by v3.0) |
| `test-e2e-learning-complete-v1.sh` | End-to-end Learning System: directory structure, configuration files, hook registration | Same sneakpeek architecture; first failing assertion is Suite 1.4 "Learning gate registered" which greps the absent sneakpeek config |

The two suites share a root cause (`~/.claude-sneakpeek/` assumption).
Archiving them together makes the cleanup atomic — reverting one
without the other would leave a half-fixed build.

## What still passed before archiving

Phase 6 of `test-learning-integration-v1.sh` (validate
`docs/implementation/FASE_1_COMPLETADA_v2.81.1.md` and
`FASE_2_COMPLETADA_v2.81.2.md`) continued to pass on a bare checkout
thanks to the `REPO_ROOT=BASH_SOURCE` fix from #55 (T2). The other
phases failed on the user-install assertions, so the verdict is
"removed": the architecture it tested is gone.

## What was decided

The human, weighing the option of deleting versus archiving, chose
**archive**. Same principle as `tests/archive/v2-suite/` (T11):
nothing was deleted, the test code is preserved for anyone who needs
to understand what the v2.x learning wrapper looked like, or to
revive it under a new name.
